Demo script (8 steps)
  1. Asks about most recent order. Say Hi, this is Anna Weber, my phone number is +49 30 1234567. Can you tell me about my most recent order? Watch: find_customer, then get_order HM-1042. State shows Anna Weber (vip), orders HM-1042 processing and HM-0977 delivered, active order HM-1042.
  2. Interrupts the agent. Start talking while the agent is still reading the order back (voice), or send the next line while it is still answering (text). Watch: clear_audio arrives, playback stops at once, the cut agent line is struck through and marked (interrupted), the latency row for that turn is marked cut.
  3. Switches to a damaged item from an earlier order. Say Actually, wait. I have a problem with a lamp from an earlier order, it arrived damaged. Watch: get_order HM-0977, then check_resolution_options with issue damaged. Active order becomes HM-0977.
  4. Agent determines resolution or escalation. The lamp is EUR 240, above the 200 limit, so the playbook flags escalation. If the agent asks whether to open a case, say Yes please, go ahead with that. Watch: apply_resolution is blocked with an escalate-instead reason if the model tries it, escalate_case returns a case id, Cases goes to 1 and the agent reads the id to you.
  5. Returns to the original order and asks for Friday. Say Ok. Back to the sofa cover order. Can you move the delivery to Friday? Watch: get_order HM-1042 (or straight to get_delivery_slots). HM-1042 is still processing so it can be moved. Friday is 4 September 2026 (Sunday 6 September is skipped in the slot list).
  6. Valid slots and choice captured. The agent offers Friday 4 September, 09-13 or 13-18, from get_delivery_slots. Say The morning slot on Friday please. Watch: Pending in the state panel shows reschedule HM-1042, date 2026-09-04, window 09-13. If the model tries apply_resolution now it shows NEEDS_CONFIRMATION or a blocked row; the ledger stays empty.
  7. Confirmation asked. The agent asks one question: shall I move it to Friday 4 September, 09-13? Nothing has been applied yet. Watch: Applied is still 0. A reply with a question mark or a no/wait/not in it can never pass the guard.
  8. Executed exactly once. Say Yes, confirm. Watch: apply_resolution ends with APPLIED and a receipt. The receipt id appears in green in the state panel, Applied goes to 1, Pending clears.
  9. Retry shows ALREADY_APPLIED. Say Yes, confirm. again, or Book that Friday morning slot again, just to be sure. Watch: apply_resolution is blocked (or ends) with ALREADY_APPLIED and the same receipt. Applied stays 1, the receipt id does not change.

Other paths, after Reset session: Jonas Berg (HM-2305, standard tier), order HM-1010 is 4 days late, EUR 15 compensation after a yes, and no slots because it already shipped; the ceramic vase set from HM-1031 arrived broken, stock is 0 so the only option is a EUR 45 refund.
